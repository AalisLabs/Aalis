# plugin-webui-client — WebUI 前端

**包名**: `@aalis/plugin-webui-client`  
**源码**: `packages/plugin-webui-client/src/main.tsx`（前端入口；托管方见 `packages/plugin-webui-server/src/client-discovery.ts`）

## 概述

Aalis 默认 WebUI 前端：React SPA 的**纯静态资源包**。它**不是插件**——没有 `apply`、没有 `meta`，
runtime 不加载它；打包产物由 `@aalis/plugin-webui-server` 托管。

## 包声明

```jsonc
// package.json
{
  "aalis": { "client": true },   // 前端标记：webui-server 据此发现
  "keywords": ["aalis", "aalis-interface"],
  "files": ["dist"]              // 构建产物 dist/index.html + 静态资源
}
```

## 配置

无配置项。

## 工作方式

1. 构建脚本 `tsc --noEmit && vite build` 先做类型检查，再产出 `dist/index.html` 及静态资源
2. webui-server 在 `app:ready` 时由 `client-discovery.ts` 扫描：`package.json` 标了
   `aalis.client: true` 且存在 `dist/index.html` 的包即为前端候选（不认任何具体包名）
3. webui-server 把每个候选注册成一条 `webui-client` 服务 provider（`getClientDir()`）
4. 活跃前端 = `webui-client` 的服务解析结果（`servicePreferences['webui-client']` 偏好 >
   provider 优先级 > 注册顺序），由 webui-server 挂成 Express 静态目录；切换偏好即实时重挂，
   并经 `/admin` 推 `client.reload` 让页面重载，无需重启

第三方要换前端，正解就是照上面打 `aalis.client` 标记（详见 `docs/services/webui.md` 第 4b 节），
不需要写插件。

## 主题与首帧

- 当前主题由 `<html data-theme>` 决定，值是主题 id。内置主题（见 [api-webui](../api/api-webui.md) 的「主题」一节）在构建时经 `parseTheme` 校验，写成按 `data-theme` 取值的规则内联进 `index.html` 的头部，第一帧就有颜色。
- `public/theme.js` 是同源的首帧主题脚本，紧跟在内联的内置主题规则后面、在打包的脚本之前同步执行：按存着的外观选择写上 `data-theme`，跟随系统时在系统切换深浅时跟着换。外观选择存在本浏览器的 `aalis.appearance`（JSON）：`{ follow: true, dark, light }` 分别指定深色、浅色用哪个主题，`{ follow: false, theme }` 固定一个；没存过、存坏了或存储不可用时跟随系统，用 `calm-dark` 与 `calm-light`；选中的主题没有规则（改了名、没写主题）时按系统深浅用这两个之一，页面不会没有颜色。
- 字号、间距、尺寸、圆角、阴影与层级的令牌在 `src/styles/tokens.css`，尺寸用 rem，跟随浏览器与系统的字号设置；触屏（`pointer: coarse`）上控件、行高与输入框字号换成触屏值。主题只改颜色，这些令牌不随主题变。

## 浏览器存储

界面偏好只经 `src/storage.ts` 读写，键带 `aalis.` 前缀，值是 JSON；隐私模式或封装禁用存储时读写失败按没存过处理，页面照常可用。首帧主题脚本是唯一直接读存储的地方。现有的键：

| 键 | 内容 |
|---|---|
| `aalis.appearance` | 外观选择，见上一节 |
| `aalis.panels` | `{ left, right }`：常驻宽度下左栏与右侧面板是否展开，存坏了按两侧都展开 |

## 外壳与地址

从左到右是图标栏、左栏、主区、右侧面板，栏宽固定（左栏 16.5rem、右侧面板 22.5rem），不可拖。当前会话、右侧面板的标签、房间表的组与打开的页面都由地址决定（`src/routes.ts`），能收藏、能刷新：

| 地址 | 内容 |
|---|---|
| `/` | 首页：桌面上是空白的新会话；手机上是第一层（会话列表） |
| `/new` | 空白的新会话；手机上是第一层之后的第二层，桌面上重定向到 `/` |
| `/s/:sessionId`、`/s/:sessionId/:tab` | 会话；带标签时右侧面板打开在那个标签（`plan`、`settings`、`usage`） |
| `/s/:sessionId/p/:instance/:pageKey` | 会话，右侧面板打开在插件的这个会话面板页面 |
| `/rooms?instance=`、`/rooms?platform=` | 一组房间的房间表；还没记下实例的房间按平台成一组 |
| `/p/:instance/:pageKey` | 位置为插件详情的声明式页面，占整个主区，没有左栏；查询串里的 `tab` 是选中的标签，`detail` 与 `row` 是选中看详情的组件与行 |

认不出的地址回首页。

- **图标栏**：上方是「会话」，一条细线下面是 owner 固定的页面，按记录的顺序，多了在这一段里纵向滚动；插件不能自己进图标栏。每项是图标，悬停提示与读屏标签写名字（多实例插件带实例名），触屏上图标下方写短名。当前项左侧一条金色指示条，另有底色与 `aria-current`；在会话区时点「会话」收起或展开左栏，打开着插件页面时点它回到刚才的会话地址。页面表或布局记录没取到时，固定区的末尾多一个警示图标，读屏标签与悬停提示写明原因，点它重试；手机第一层的「固定的页面」里写出原因与「重试」。
- **宽度**（断点用 em，跟随字号设置）：

  | 宽度 | 布局 |
  |---|---|
  | ≥ 80em | 全部常驻；`Cmd/Ctrl+B`、`Cmd/Ctrl+Alt+B` 收起或展开左栏与右侧面板，收起状态存在 `aalis.panels` |
  | 64em–80em | 图标栏、左栏常驻；右侧面板从右边覆盖进来，不挤压主区 |
  | 48em–64em | 图标栏与主区常驻；左栏与右侧面板是覆盖式抽屉 |
  | < 48em | 手机：没有图标栏，按地址分三层逐级进入，每层占满一屏：`/` 是第一层，顶栏左边写「会话」，右边是搜索与新会话两个图标按钮，固定的页面列在会话列表上面；会话、新会话、房间表与页面是第二层，右侧面板的标签（含插件的会话面板）是第三层（用量除外，它从底部弹出，仍在第二层）；系统返回手势与浏览器后退按地址逐层退回，每层头部左边有回上一层的按钮：上一条历史就是上一层时等于后退一步，否则换掉当前这条，两种都不多留历史；用量弹层关上时同样退回 |

  抽屉打开时焦点移进去，Esc、点遮罩或在左栏里跳到别的地址都会关上，关上时焦点还给打开前的元素。
- **连接状态**：主区顶部一条横条，会话连接或管理连接断开、重连中时写「连接断开，正在重连…」，重连上写「已恢复」两秒后收起，平时不出现。会话服务不在（`/session` 以 1013 关闭）不算断线，会话列表与主区写「会话服务未启用」，服务回来后自动连上。收到 `app.restarting` 时横条写明正在重启，管理连接重连上以后整页重新加载；收到 `client.reload` 立即重新加载。
- **快捷键**：按平台取 ⌘ 或 Ctrl，另一个修饰键按下时不算；不占浏览器保留的 ⌘N、⌘T、⌘W、Ctrl+Tab。

  | 键 | 作用 |
  |---|---|
  | `Cmd/Ctrl+K` | 搜索会话：按名称、id 与「平台:群号」搜，方向键选、回车打开；输入法组字时的回车不算 |
  | `Cmd/Ctrl+Shift+O` | 新会话 |
  | `Cmd/Ctrl+B`、`Cmd/Ctrl+Alt+B` | 收起或展开左栏、右侧面板 |
  | `Esc` | 正在生成时停止这一轮；有弹层（对话框、菜单、抽屉）或就地编辑（设置行、拒绝的理由）时先收起它们，输入法组字时的 Esc 不算 |
  | `Enter`、`Shift+Enter` | 在输入框里发送、换行；输入法组字时的回车只上屏；触屏上回车换行，用按钮发送 |
- **标签页标题**：握手给出的应用名（宿主配置的 `name`，握手之前是页面自带的「Aalis」）；推到这个页面、还没结算的审批有几张，标题前就带上「(N)」。

## 会话列表

左栏的会话列表经 `sessions/list` 翻页取全（一页 200 条），之后按 `sessions/changed` 的增量即时更新，断线重连后重取。翻页途中收到推送时排序可能变了、后面的行会挪进取过的页，所以重取，最多三遍。

- **我的**：owner 自己的会话，需要我处理、出错、完成未读、运行中依次排前，其余按最后活动。行首标记只给需要我处理（金）、出错（红）、完成未读（强调色）；需要我处理、出错、运行中在第二行写一句状态。
- **房间**：按适配器实例分组，组头写通用图标、组名（`RoomGroup.label`）、房间数与需要处理的数（不按平台分图标，房间表的标题同样），另有「表格」按钮打开这一组的房间表。组默认折叠，有需要处理的自动展开；展开时只露出需要处理、出错、运行中、正在看的与近 7 天她开过口的房间，其余收在「其余 N 个」里。同一实例带多个账号时行内标出账号。房间行是单行，不正常时状态代替时间写在右侧。
- **子任务**：有子会话的行尾有展开按钮，展开后子会话挂在这一行下面。
- **已归档**：列表底部，默认折叠，展开时按 `archived: true` 取。
- 行整行可点；行尾的「更多」收改名、归档、删除（已归档的是恢复、删除），悬停、选中、键盘聚焦时出现，触屏上常显，手机上不带。归档直接做，Toast 带「撤销」；删除先确认，确认框点名对象、写明会清空长期记忆，焦点落在「取消」上。

## 房间表

`/rooms?instance=<实例>`（或 `?platform=<平台>`）一次取全这一组的房间，列有名称、类型、账号（多账号时才有）、状态、最后活动、她最近开口。类型与状态的筛选写进地址（`type`、`status`），排序、搜索与分页在客户端做，行数超过一页才出现搜索框与分页；没排序的列只在指着或聚焦表头时露出排序图标，触屏上常显。批量动作只有归档与删除，全选只作用于当前筛选结果。窄时只留名称与状态两列，名称长了折行。

## 会话工作台

`/s/:sessionId` 是一个会话：头部、时间线、输入框，右侧面板跟着会话出现。订阅一律先取快照，之后按推送更新：同一 `itemId` 原地覆盖，`item/delta` 接在正文或工具输出后面，`completed` 的全文是正本；计划与用量每个会话一条、整份替换，不进时间线。重新订阅（重连、`epoch` 变了、`session/resync`）时快照整份取代。会话被删掉（出现在 `sessions/changed` 的 `removes` 里）时回首页。看着「我的」区的会话时，她的回复不算未读：页面在前台时调 `session/markSeen`。

- **首页与新会话**：`/` 与 `/new` 是空白的新会话，发出第一条消息时先 `session/create` 再 `turn/send`，然后打开它。
- **头部**：标题、会话种类与平台（我的会话、子任务，房间写群或私聊与平台）、用量百分比、「全部展开」或「全部折叠」、会话面板（常驻宽度下收起或展开）、「更多」（改名、归档或恢复、压缩对话、删除；压缩按功能位出现）。手机上顶栏右边只有用量百分比与「更多」，「全部展开」与会话面板（进第三层）收进「更多」，标题不被挤掉。驱动房间时头部下面一条提示：「你正在以 owner 身份在「群」发言，按群的人设和能力运行」。
- **时间线**：条目按回合成段，同一回合挨在一起，相隔超过 10 分钟的两段之间插一行时间。
  - 用户消息在「我的」会话里靠右、浅底；房间是多人对话，逐条写说话人与时间，她的回复的说话人写握手给出的应用名；内部注入的消息写明来源。
  - 她的回复按 Markdown 渲染，下面一行写模型；房间里没发出去的写明原因（数据来自送达回执）。
  - 思考默认收起，点开是正文。宿主通知（压缩、工具调用达到上限等）是一行说明，进行中带旋转图标；工具调用达到上限且这一轮已收尾时有「继续」（`turn/continue`，有对话服务时才出现）。
  - 回合中止写「已停止」，出错写「这一轮出错了」。收尾了的回合右上角有回滚（悬停、键盘聚焦时出现，触屏上常显，按功能位出现）：只回滚文件，或连这一轮的对话一起删。回滚先确认：确认之前查这一轮的检查点（`turn/checkpoint`），这一轮执行过命令时写明「命令的效果不会撤回」，没查到时写明原因，查完才能确认。结果如实回报：恢复与删除了几个文件、删掉几条消息，之后的回合也改过的文件点名写出，没能回滚的写原因。
  - 「更早的消息」按快照给的游标取 `session/history`，接在前面。
  - 工具卡与思考默认收起，可以逐张展开，头部的「全部展开」「全部折叠」一起改。
- **工具卡**：一行写动作与对象、右侧写状态（正在生成、运行中、失败、已停止、已发到群、耗时，结算过的审批写成一句），点开看细节。失败用危险色，命令的退出码不为 0 时写「退出码 N」；回合停止时还没结束的调用（状态 `aborted`）写「已停止」，与回合的结局同一个说法，不用危险色。模型还在生成参数时（状态 `generating`）只写工具名与「正在生成」，不能展开；开始执行后同一张卡照常。按条目里的 `display` 渲染：`command` 写命令与工作目录，`file-change` 写路径与删、加两侧；没有 `display` 的走通用卡，逐字列出参数。前端不认识任何工具名。来自参数的文字显示前经 `@aalis/api-approval` 的 `sanitizeForCard` 清洗。
- **审批卡**：挂在要批准的那张工具卡下面，只在审批推到这条连接（快照或 `approval/requested`）时出现。标题写要做什么与工具名（「要改动文件 · file_write」）。事实取会话服务给出的命令、目录与 diff，路径或内容疑似含密钥时只给文件名，没声明展示的逐字列出全部参数，显示前一律清洗；命令、参数与 diff 完整列出，不设行数上限、不在框内滚动，长串空白后面的半截照样在卡上（服务端已按长度截断并写明省略多少）。工具卡的细节照旧限高、在框内滚动。只有「批准」「拒绝」，拒绝可附理由（`approval/respond` 带回内容哈希；理由框里按 Esc 收起理由框）；不显示倒计时，出现时不抢输入框的焦点，没有批准的快捷键。结算后卡片收起，工具行写成一句：「已批准 · 10:32」「已拒绝 · 10:32」「已按拒绝 · 没人在场 · 10:32」「已撤销 · 回合已结束 · 10:32」；发起时就被拒（没人在场、超过频率上限等）的同样写成一句；刷新后从条目的结算恢复。
- **输入框**：附件一律接收（按钮选文件或粘贴），只有附件也能发，读成 data URL 随 `turn/send` 发出，一条消息的附件合计不超过 64 MB。回合在跑、又没有要发的内容时发送键换成停止（带圆圈的停止图标，`turn/abort` 带这一轮的 `turnId`）。没有对话服务时不可用并写明原因；连接断开时也不能发。发送成功后只清掉发出去的文字与附件，请求在途时接着打的字与新加的附件留着。左下是 `composer` 档设置项的快捷切换，能从选项里选的就地选、改了即存，其余写名字与按可选项标签显示的值（没有值的只写名字），点了去「设置」标签；可选项没取到时下拉里写明原因；收到 `session/config/changed` 重取。
- **右侧面板**：宿主的标签（计划、设置、用量）与插件的会话面板在一个标签栏里，走同一套机制（`src/workbench/panel-tabs.ts`）。标签的顺序与开关取自布局记录的 `panelTabs`（见 [api-webui](../api/api-webui.md) 的「布局记录」），一个合成函数按「此刻可用」把表里开着的排成标签栏，把表里关着的与适用、还没进表的插件面板（按页面的先后）列进标签栏末尾的「+」，「+」里没东西时不出现。宿主标签的可用性写在一张宿主表里，按数据出现：计划要有计划条目，设置总有，用量要有用量数据且不是手机。关闭按钮只在当前标签上，关掉的标签（宿主的也一样）留在原位、进「+」，从「+」打开回到原位；关掉后回到不带标签的会话地址，上一条历史就是它时退回去，不多留一条历史；打开与关闭按操作写进布局记录（`open-tab`、`close-tab`），写不进去时出错 Toast；布局记录没取到时宿主标签按都开着显示，记录里有前端不认识的宿主标签（webui-server 比前端新）时按不可用跳过。别处指向标签的入口（桌面上头部的用量百分比、输入框旁的设置项）在标签关着时先打开它，写入成功再跳过去，右侧面板收起着或是抽屉时一并展开；输入框旁的设置项是链接，不是左键或按着修饰键的点按交给浏览器（新标签页打开）。标签由地址决定（`/s/:id/plan`、`settings`、`usage`，插件面板是 `/s/:id/p/:instance/:pageKey`），没写或写的标签不在标签栏里时停在第一个；标签都关了时只剩「+」，手机上从「更多」的「会话面板」照样进这一层。
  - 计划：可以清空（`plan/clear`）。
  - 设置：`session/config/get` 给出的各行，顶部写「改动从下一轮起生效」；`composer` 与 `common` 在前，`advanced` 收进默认折叠的「高级」，按登记它的插件分组，组名取插件显示名。每行写名称、来源（默认、平台档、受众、父会话、本会话）与生效值，值按可选项的标签显示（动态可选项一并取来，如工具分组的 `*` 写成它在可选项里的标签），都没设时写字段的默认值，没有默认值的不写。点行就地修改、改完即存，开关直接拨；被本会话覆盖时行尾有「恢复继承」；写不进去时原因写在行下。按字段类型渲染，前端不认识任何设置键；可选项取自字段的 `dynamicOptions`（`/api/models/:service`），模型字段（`llm-ref`）取模型服务。插件启停、别处改了设置或重连后重取。
  - 用量：头部的百分比是上下文已用占窗口的比例，弱化色，达到压缩线（`compressAt`）换警告色。拆分表写上下文窗口、已用、各分项、为回复预留与剩余，为 0 的不显示；「其余系统提示」可以展开，按注入者的插件实例合并到插件，行名取插件显示名，对不上的归「其他」。表上方一条按上下文窗口画的堆叠进度条：分项按占用从大到小取图表色（`--color-chart-1` 到 `-6`，多出的与为回复预留用弱化色），表里每行前一个同色的点作图例，剩余与条的底色相同；有压缩线时在条上标出位置，表下写明「到 N% 自动压缩」。不知道窗口时没有进度条与剩余。手机上从头部的百分比点开，从底部弹出。
  - 插件面板：位置为 `session` 的页面，默认不在表里，从「+」第一次打开时追加在末尾，在所有适用的会话里出现。哪些适用由 `GET /api/session-pages?sessionId=` 按会话取，换会话、插件登记表变了、会话面板页面推来不带会话或带本会话的 `page.invalidate`、管理连接重连后重取。面板里的页面只有手动刷新，放在标签栏里「+」的前面，不另占一行；取数与动作都带上当前会话。适用的页面、页面表或布局记录没取到时「+」前面多一个写明原因的按钮，点它重试，「+」照列已知的。
  - 插件的显示名取自 `GET /api/plugins`，插件登记表变了（`plugins.changed`）或管理连接重连后重取；没取到时写明，按插件实例 id 显示。
- **Markdown**：她的回复、思考与插件给的文字都不可信。原始 HTML 当文字显示；图片只认媒体地址（`/api/media` 与存储地址），外站图片显示成链接、不发请求；链接只许 http、https 与 mailto，外链在新标签页打开；公式（KaTeX）不信任输入；单个 `~` 不是删除线（`~~删除~~` 照常）；行内公式是 `\(...\)`、单行的 `$$...$$`，以及按成文规则认出的单美元（开头的 `$` 右边紧跟非空白；结尾的 `$` 左边紧跟非空白、右边不紧跟数字或 `$`，以免和相邻的 `$` 连成 `$$`；同一行，中间没有未转义的 `$`），认不出的单美元按字面显示，「$5 和 $10」不会成公式；代码（包括流式输出时还没闭合的围栏）与链接地址里的不当公式；代码块按语法色令牌高亮，剪贴板可用（安全上下文）时悬停出现复制按钮，触屏上常显，代码从按钮下面开始、不被它压住；Mermaid 用到时才加载，用严格安全级别，颜色取自当前主题的令牌，换主题后重画；所在的消息还在输出时只显示源码，输出完才画。
- **附件**：图片、音频、视频按媒体地址经 `/api/media` 取，外站图片经 `/api/proxy/image`；她发出的文件按句柄经 `/api/session-file` 下载，没有句柄的只写名字。

## 声明式页面

插件页面只交声明（[api-webui](../api/api-webui.md) 的「声明式页面」一节），由这里统一渲染，前端不认识任何插件的页面键与动作名。页面表取自 `GET /api/pages`，布局记录（固定的页面、会话面板的标签）取自 `GET /api/layout`，整页各取一份：页面表在 `plugins.changed`、布局记录在 `layout.changed` 后重取，管理连接重连后两样都重取；重取失败时留着上一次的，打开着的页面与对话框不受影响，原因写在固定区。

- **标题栏**：标题，带实例后缀的实例另写实例名（弱化色），手动刷新；位置为插件详情的页面另有「固定」（按下态，再按一次取消），按操作写进布局记录（`POST /api/layout`），写不进去时出错 Toast；布局记录没取到时「固定」换成一个写明原因的按钮，点它重试。会话面板里的页面只有刷新，标签就是标题，刷新放在标签栏里。
- **页面不在**：地址里的页面不在页面表里（所属插件停用或卸载）时显示「这个页面所属的插件已停用」，页面重新登记后自动回到原页；页面表没取到时写明原因，可以重试。设置里的一节不在 `/p/` 下显示。
- **取数**：每个组件打开时按 `GET /api/pages/:instance/:pageKey/data/:componentId` 取一次（会话面板带 `sessionId`，详情里的带选中的 `rowKey`），`page.invalidate` 指到它时重取：带组件 id 的只重取这个组件，带会话的只让打开着这个会话的面板重取。手动刷新与管理连接重连后整页重取。一块取数失败只影响这一块：原地写明原因，可以重试。
- **排法**：竖排的组件，或者标签页（选中的标签写进地址，切换用替换，不多留历史；标签放不下时横向滚动）。表格与关系图带详情时是主从：选中一行（点行或点行首的链接）写进地址，从没选中到选中是新的一条历史，后退回到列表；宽时详情在右边、占得比列表多（列表窄了就按表格的规则只留标了 `primary` 的列），窄时详情代替这一屏（同一屏的其他组件收起），头部是「返回列表」。地址里选中的行已经不在时不显示详情。
- **组件**：
  - 表格：复用房间表的表格，排序、搜索与分页在客户端做，行数超过一页才出现搜索框与分页；纯数字的列右对齐、等宽数字；窄时只留标了 `primary` 的列，都没标时留第一列，带详情的表格另留选中用的那一列，长的状态折行。行动作按 `visibleWhen` 显示；宽时第一个不是 `destructive` 的动作是文字按钮，其余进「更多」，窄时全部进「更多」；这一行有动作还没回来时写「进行中」。没有行时写声明的空状态。
  - 关系图：力导向排一次就定住，节点与边按类别的 `tone` 取 `--color-chart-1` 到 `-6`，没有类别的用中性色；上方的图例只列这张图里有的类别，节点类别画成圆点、边的类别画成短线；滚轮、双指与拖动缩放平移，角上有放大、缩小与复位；带详情时节点是按钮，选中的节点在详情里看；鼠标点选不留浏览器给 SVG 元素的默认焦点框，键盘聚焦照常有焦点环。
  - 键值：名称一列、值一列，数字用等宽数字。文字：按 Markdown 渲染，规则同下面「会话工作台」的 Markdown。按钮组：次要按钮，`destructive` 是危险色字的文字按钮；详情里的按钮组作用于选中的那一行。
- **单元格**：文本、时间（今天写时分，别的日子带日期，悬停看完整时刻）、倒计时（每秒走，到零写「已到时间」，不重取）、链接（只认 http、https，新标签页打开，别的按文字）、状态（需要处理警告色、出错危险色、进行中带旋转图标、停用弱化色，正常不上色；宽时不在中间折行，窄时折行而不撑出横向滚动）、代码、长文本（收起时只占一行、末尾省略，按可折行的文字算宽，窄时不按全文撑宽所在的列；点开看全文）、图片（只认宿主换好的 `/api/media` 地址，懒加载，别的按文字）、文件（有句柄时是 `/api/page-file` 的下载链接，没有的只写名字）。
- **动作**：`destructive` 由宿主弹确认框，标题是按钮上的字加问号，正文是插件给的确认文案（没给时写「这个操作不能撤销。」），焦点落在「取消」上；带 `input` 的弹一个单列的小表单（手机上从底部弹出），控件按字段类型（文字、数字、多行、列表一行一项、映射一行一个「键=值」、选择与动态可选项、多选、开关是复选框），必填的写「必填」，行动作里与行字段同名的输入项用这一行的值预填（「编辑」），其余取字段的默认值；`destructive` 的表单开头同样写确认文案（没给时写「这个操作不能撤销。」）。提交时空着的可选项不送，读不出的（不是数）写在字段下，服务端逐项的问题写回对应的字段、表单不关。其余直接调。发出后到回来，这个动作在这一行上算进行中（按钮或行上写「进行中」）；确认框与表单在回来之前可以关掉，请求照常进行，回来时只关发起它的那个。成功时处理函数给的一句结果用 Toast 显示，失败时出错 Toast 写原因（表单还开着时写在表单上）。结果变了由插件 `invalidate`，界面不自己重取。
- **图标**：只按 lucide 图标名查，没写或不认识的用通用图标；图标名的对照表单独成块，用到页面图标时才加载，每个图标也是用到时才加载。
- **宽度**：组件按容器宽度变形（容器查询），会话面板与手机共用一套规则：表格窄于 36em 时只留标了 `primary` 的列、行动作全部进「更多」，写字的格子折行（没有断行机会的长串也在格子里断开，数字列不折），不把后面的列挤出视野；一屏窄于 36em 时关系图矮一些，窄于 56em 时主从的详情代替这一屏。

## 连接

- 两条 WebSocket：`/session` 是会话协议（[api-session-protocol](../api/api-session-protocol.md)），`/admin` 是管理面推送（[api-webui](../api/api-webui.md) 的「管理面推送」一节）。地址由页面所在的源推出，https 的页面连 wss。
- 断开后按 1、2、5、10、30 秒退避重连，连上一次就从头算；网络恢复或页面回到前台时立即重试。一次也没连上就断开时查一次 `GET /api/auth/status`，登录失效就重新加载页面，由服务端给出登录页。
- 会话连接先握手才算连上；主版本不兼容时停止重连并给出服务端的原因。断开时还没回应的请求以「连接断开」失败，不重发；还没握手时发起的请求等握手完再发。
- 订阅一律先取快照，之后的推送按 `epoch` 与 `seq` 去重；`epoch` 变了或收到 `session/resync` 时重新订阅。重连后重新握手、`sessions/watch` 并重订打开着的会话。管理面的事件断线期间不补发，重连上以后通知界面重取。
- 在场：页面可见且最近 10 分钟有键盘或指针活动算在场。有活动时报在场（持续活动时每分钟最多一次），转到后台报不在场；重连后若仍算在场就立即重报。服务端从上报的时刻算 10 分钟，所以报在场之后，到最近一次活动满 10 分钟时还没有新活动就报不在场。打开页面本身不算活动。

## 兼容与写法

- 构建目标是近两年的 Chrome、Edge、Firefox 与 Safari 16 起。页面只在源的根上提供，不支持挂在反向代理的子路径下。静态资源一律是同源的文件，不内联成 `data:` 地址：webui-server 给的文档级 CSP 里字体只许同源。
- 写法由 `test/architecture/webui-client-guards.test.ts` 守住：颜色只来自主题令牌，组件样式不写 px（线宽 1px、2px 除外），内联 `style` 只设 CSS 变量，不用原生 `alert`、`confirm`、`prompt` 与 `window.open`，浏览器存储只经存储模块，不写死主机与端口，`dangerouslySetInnerHTML` 按文件白名单；源码不出现插件包名，字符串字面量不等于任何插件登记的页面键、动作名或设置键（与会话协议、管理面事件同名的字段除外）。
- 端到端测试在 `test/e2e-webui/`：构建前端，起 create-aalis minimal 档加 webui-server 的运行时（假模型、内存记忆），在无头 Chromium 里按桌面（1280 宽）与手机（390 宽、触屏）两种宽度走打开、发消息与流式回复、代码块的复制按钮（桌面悬停出现，触屏常显、不压住第一行）、审批的批准与拒绝、切会话、断线重连、刷新与主题，并核对最少插件组合下计划、回滚与压缩的入口、图标栏里的页面与会话面板的「+」都不出现。声明式页面用一个探针插件登记，核对表格与详情按宽度变形（窄时长的字折行、表格不用横向滚动）、长文本与状态单元格、关系图的图例与缩放按钮、插件推来 `page.invalidate` 后页面更新、从标题栏固定与取消（手机上看第一层的「固定的页面」）、插件停用时的占位与重新启用后回到原页、会话面板的标签从「+」打开、关闭后进「+」并回到原位（宿主标签与插件标签一样，刷新在标签栏里）、两台设备同时固定；另装迁移过来的计划任务与工作流，走带输入的动作（新建、按行预填的编辑）、destructive 的确认与表格详情。页面里的未捕获异常、CSP 拦下的加载与回 4xx、5xx 的请求都算失败。
