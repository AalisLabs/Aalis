# plugin-reach — 触及：一次工具调用能碰本机的什么

**包名**: `@aalis/plugin-reach`  
**源码**: `packages/plugin-reach/src/index.ts`  
**契约**: [api-reach](../api/api-reach.md)（服务描述符 `reach`、凭据与沙箱策略的类型、触及的纯函数）

## 概述

按一次工具调用签发触及凭据。凭据回答「这一次调用能读写哪些文件、命令在哪执行、能不能联网」：工具从调用上下文取得凭据后转交给存储与沙箱，路径类目标要先经 `require` 判过。只有 owner 在受众只有 owner 的会话（WebUI 与终端的会话、owner 的 IM 私聊、项目会话）里有本地效果；群、别人的私聊与内部会话一律没有，owner 在群里也一样。

另管四样东西：本会话临时区、子进程环境、会话的污点、白纸的来源账本。

## 插件声明

```ts
definePlugin({
  name: '@aalis/plugin-reach',
  displayName: '触及',
  subsystem: 'authority',
  provides: [reach],
  uses: {
    provide,
    events,
    lifecycle,
    logger,
    paths: hostPaths,
    sessionManager,
    storage,
    authority: optional(authority),
    process: optional(processService),
  },
  apply: run,
});
```

- `authority` 缺席时谁都不是 owner，凭据一律没有本地效果。
- `process` 缺席时取不到 login shell 的环境，子进程用守护进程的环境。

## 签发凭据

`forCall(call)` 的输入与执行守卫同一口径（会话、平台、发言者、授权身份、入站回合），按下面几项交给 api-reach 的 `resolveReach`：

| 输入 | 取法 |
|---|---|
| 主体 | 权限服务的 `originOf(call)`：`owner` 与 `owner-chain` 为 owner；`subtask` 见下文「子任务」；其余（自主回合、房间、别人、没有回合的调用）没有本地效果 |
| 房间类别 | api-session-manager 的 `roomClass`，子会话取根会话的；owner 判定取权限服务的 `isOwner` |
| 档位、越界策略 | 根会话的生效设置 `accessTier`、`accessOnBoundary`（子会话不读自己的，按根会话实时取）；哪一层都没设时为工作区档、越界要问 |
| 场所的主目录与白纸 | 项目会话（根会话带绑定）的主目录是绑定目录，其余是默认工作区的白纸；白纸取默认工作区的白纸（`stage/paper/` 下场所键 `workspace:default` 的白纸目录） |
| 绑定 | 根会话的附加可写目录与本会话树建的 worktree |
| 仓库的 git 目录 | 从绑定目录往上找 `.git`（见下文） |
| 污点 | 这个会话记下的来源（见下文「污点」） |
| 本会话临时区 | `tmp/sessions/<会话 id 的 base64url>/` |
| 三张清单 | 激活时算好（见下文「清单」） |

主体、绑定与仓库的 git 目录在签发时取好；档位、越界策略、房间类别、污点与子任务的父会话在每次判定（`require`、`allows`、沙箱策略、`noteWrite`）时取当时的，签发之后降档或受污染，已签发的凭据立即随之收紧。凭据上的 `tainted` 按签发时取，全权档不带（全权不提示，确认卡上也不写来源），来源账本照样记。

宿主通知开的回合（后台任务结束后的续做）按接收会话的房间类别算：owner 会话里的续做有本地效果，群里的没有，通知里快照的授权身份抬不高它。

### 子任务

子任务的主体随发出任务消息的那一轮父会话：子任务插件在父会话的一轮里发出任务消息（`source` 为 `subtask`）时，本插件记下那一轮的主体（父会话最近一次签发凭据时的主体），这条消息之后的子任务回合按它算。

- 那一轮是 owner 的：子任务的触及与父会话实时的触及取较小值——档位取较低的，越界策略任一为拒即拒，污点并上父会话的；父会话之后降档或受污染，子任务随之。
- 那一轮不是 owner 的（定时任务等自主回合），或父会话里没签发过凭据：子任务没有本地效果。之后 owner 在父会话里发言也抬不高它，要等 owner 的一轮再发任务消息。

### 仓库的 git 目录

项目会话的绑定目录在 git 仓库里时，仓库的 git 目录（共用的那个）在工作区档可写，落点（钩子、配置）除外；绑定在 worktree 上时，它在 worktree 之外，要另算进来。从绑定目录往上找 `.git`：目录形式的就是它，链接到目录的按它指向的目录算；文件形式的（worktree、子模块）按里面的 `gitdir` 与 `commondir` 找到共用的那个，读不到时按不在仓库里。找到的目录没有 `HEAD` 与 `objects` 时不算，免得一个 `.git` 把任意目录指成可写；不论算不算，找到 `.git` 就不再往上找外层仓库。仓库的其他 worktree（包括正在跑生产的那一份）不在可写范围里。

### 回给模型的话

`require` 判不行时回一句话：要做什么、为什么不行、能不能申请。

- 宿主控制面与拒读清单：写明不可申请，不要尝试绕过；
- 越界策略为直接拒绝的：写明原因与越界策略；
- 要问 owner 的：写明原因，并说明这里没有可用的审批；
- 没有本地效果的：写明读写文件、执行命令只在 owner 自己的会话里可用。

## 清单

三张清单（宿主控制面、持久化与自动执行落点、拒读清单）在激活时按家目录布局、操作系统用户的家目录与平台生成一次，工具边界与沙箱用同一份，规则见 [api-reach](../api/api-reach.md#三张清单)。

- 比较一律用真实路径：安装集与用户家目录先取真实路径，安装集经符号链接给出时按它指向的目录。
- 守护进程加载的代码：安装集的依赖解析到安装集以外的目录（经链接装进来的插件与库）也归宿主控制面。取法是看安装集 `node_modules` 下每一项（含 `@scope/` 下的）的真实路径，落在安装集以外的整个目录都算；源码形态下 `packages/` 里链接到安装集以外的包，与安装集里的包一样只算它的 `dist` 与 `node_modules`。断掉的链接、不是目录的 `@scope` 跳过。
- 覆盖不到的：依赖没装进安装集、守护进程按 Node 的规则从更上层目录的 `node_modules` 加载的包。

## 本会话临时区

`tmp/sessions/<会话 id 的 base64url>/`，权限 0700。

- 有本地效果的调用签发凭据时建好；没有本地效果的不建。
- 删除会话时删。
- 启动时与每天清扫一次：7 天没有改动（目录与它下面任何一项的修改时间都早于 7 天前）、会话也不在运行的删掉；会话表里查不到的同样按 7 天算，不立即删（会话表读不出时表是空的，不能当作会话都删了）。删之前再查一次会话在不在运行；遍历时被别处删掉的这一轮不动。名字不是某个会话 id 编码的目录不动。

插件自己的临时目录（浏览器截图、代码执行的脚本目录）不在这里，清扫不碰。

## 子进程环境

凭据的 `processEnv(mode)` 是子进程环境的唯一来源，工具只转交。

- **来源**：在场所的主目录下用 owner 的 login shell（`SHELL`，没有时取操作系统账户登记的）取完整环境（交互式登录 shell，`-i -l -c`，限时 10 秒），缓存在内存、不落盘；同一个主目录取到一次就一直用，同时来的调用共用一次取。主目录还没建（白纸首次写入时才建）时在用户家目录下取。取不到（没有 shell、超时、失败、没有进程服务）时用守护进程的环境并记一条告警，1 分钟内沿用，之后的调用再取一次。
- **宿主执行**（`host`）：完整的 login shell 环境。
- **沙箱内**（`sandbox`）：
  - 去掉 `AALIS_*`、`SSH_AUTH_SOCK`、密码管理器的会话令牌（`OP_SESSION_*`、`BW_SESSION`）、名字像凭据的变量（含 `TOKEN`、`SECRET`、`PASSWORD`、`PASSWD`、`PASSPHRASE`、`CREDENTIAL`、`APIKEY`、`SSHPASS`、`WEBHOOK`，或按 `_` 分段后有 `KEY`、`KEYS`、`PAT`、`PASS`、`AUTH`、`COOKIE` 一段的），以及值里带密码的网址（`://<用户>:<密码>@`，用户名可以为空；只有用户名的照留）；HOME 保持 owner 的。
  - git 的命令行配置（`GIT_CONFIG_COUNT` 与各组 `GIT_CONFIG_KEY_<n>` / `GIT_CONFIG_VALUE_<n>`、`GIT_CONFIG_PARAMETERS`）整组去掉：值里可能是凭据（如 `extraheader` 的认证头），只去掉其中一项又会让 git 读不出配置。
  - 注入 `npm_config_userconfig`：本会话临时区里的 `npmrc`，是用户家目录 `.npmrc` 去掉凭据行（令牌、用户名与密码、客户端证书与私钥，文件或内联）的副本，镜像源与作用域注册表照留；没有 `.npmrc` 时是空文件。临时区在沙箱里可写，副本先以随机名独占创建、再改名盖过去，沙箱里的命令把 `npmrc` 换成符号链接也改写不到别处；临时区本身不是目录（被换成了链接）时拒绝。npm 的环境变量不分大小写，同名的旧值先去掉。
  - 注入 `npm_config_nodedir`：这份环境的 PATH 上第一个 `node` 所在的安装，带头文件（`include/node/node.h`）时才给。
  - 注入 `PUPPETEER_CACHE_DIR`（本会话临时区下的 `puppeteer`）与 `npm_config_side_effects_cache=false`（沙箱里构建出的产物不进 pnpm 的共享缓存）。
  - 经 `GIT_CONFIG_COUNT` 与 `GIT_CONFIG_KEY_<n>` / `GIT_CONFIG_VALUE_<n>` 注入（从 0 编号）：`github.com`、`gitlab.com` 的 SSH 地址拉取时改走匿名 HTTPS（`insteadOf`），推送仍是 SSH（`pushInsteadOf`）；沙箱里没有 SSH 凭据，推送与私有仓库拉取要宿主执行。

没有本地效果的凭据调 `processEnv` 抛错。

## 污点

会话读进过别人写的内容即受污染，污点记的是来源称呼（场所的显示名、对方昵称、工具名等）。`markTainted(sessionId, sources)` 记下来源：至少一个、不能是空白，否则抛错；同一来源只记一次。污点粘在会话上，之后签发的凭据都带着（`tainted`，全权档不带），已签发的凭据判定时也随之；全权以外的档位里，受污染的会话把送出会话的动作（模型给的任意网址、要联网的命令、写技能目录、写编排定义）改成问。子任务的污点并上父会话的。

## 来源账本

受污染的会话经凭据写进白纸（`stage/paper/` 下）的文件记进来源账本：真实路径 → 写入会话、来源称呼与时间（凭据的 `noteWrite`）。干净的会话写的、白纸以外的文件不记。`provenanceOf(realPath)` 取一条记录；没有记录的文件按 owner 写的算。

## 持久化

污点与来源账本落在插件数据 `pluginData:/reach/provenance.json`（家目录的 `state/plugins/reach/provenance.json`），整份写，改动之后排队写盘，停用时等写完。写盘失败记一条错误，本次运行里照常生效，下一次改动再写整份。

文件不存在时从空起步；存在但读不出或形状不对时插件不激活，日志写明文件位置与原因：从空起步等于当作谁都没读进过别人的内容。修好或移走文件后重启。
