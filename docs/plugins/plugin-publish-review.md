# plugin-publish-review — 作品审核

本插件提供 `publish` 服务，接收 [白纸](plugin-paper.md) 等插件提名的文件快照，执行静态检查、媒体元数据剥除、离线渲染与模型分类，通过后写入独立的公开存储根。它不负责 Cloudflare 部署；网址通知要等 [作品站](plugin-works-site.md) 核对上线。

## 配置与使用

```yaml
plugins:
  '@aalis/plugin-publish-review':
    reviewEnabled: true
    manualReview: false
    textClassifier:
      provider: '<模型提供者实例 id>'
      model: '<模型 id>'
    imageClassifier:
      provider: '<具备视觉能力的模型提供者实例 id>'
      model: '<模型 id>'
    ownerTimeoutHours: 12
    ffmpegPath: ffmpeg
    chrome:
      headless: true
      executablePath: ''
```

`reviewEnabled` 默认 `true`。设为 `false` 时，不执行内容标记、模型分类或人工内容审核，文件处理成功后自动发布。格式、大小、路径、元数据剥除、发布目标授权和公开文件写入后的字节核验仍执行；处理或核验失败的作品不会发布。旧的待人工裁决作品（包括自动审核未通过的回退项）会重新排队，按当前配置处理，不沿用旧审核结论。

内容审核启用时，`manualReview` 默认 `false`，表示自动审核通过的作品可继续发布，不要求每件作品人工批准。自动审核拒绝、拿不准或模型调用失败时，作品先被拦截并进入人工队列；审核者可查看自动结论和证据，再批准或拒绝。设为 `true` 时，自动审核通过的作品也须等待人工批准。结构检查或内容净化失败的作品始终阻断，不能由人工强行放行。关闭每件人工要求后，仅因该要求而等待的作品重新自动审核；自动未通过而转人工的作品继续等待裁决。

内容审核启用时，两个模型配置都按提供者与模型精确匹配。`imageClassifier` 留空时使用 `textClassifier`，该模型必须具有视觉能力。模型、浏览器或沙箱不可用时不会静默跳过检查。诊断页的 `publish-review.tools` 会指出缺少哪项能力。关闭内容审核时不要求分类模型和离线渲染浏览器；媒体文件的元数据处理仍可能需要沙箱与 ffmpeg。ffprobe 取 ffmpeg 的同级路径。

`chrome.executablePath` 留空使用内置浏览器；写成非字符串或相对路径时拒绝激活，不悄悄换用内置浏览器。`ffmpegPath` 写绝对路径或 PATH 里能找到的命令名，相对路径同样拒绝激活；留空时回到默认的 `ffmpeg`，不会以空命令运行。激活失败时审核插件整体不可用，WebUI 的审核入口随之消失，应先修正配置。

`limits` 默认每文件 25 MiB、每作品 50 文件且总计 50 MiB、最多 20 件待审、每来源 3 件待审、每来源 24 小时内 10 次提名。拒绝和撤回仍占已受理的每日提名配额。动态 PNG、动态 WebP 暂不接收；可转换为 GIF 或 MP4。内容审核启用时，视频的声音不由图像分类器审听，因此有音轨会判为需要进一步确认。

## 可见入口

WebUI 插件详情里的「作品审核」页（`key: 'publish-review'`）分「待裁决」「审核中」「没发出的通知」「历史」四个标签。「待裁决」标签顶上是几个计数（待裁决、审核中、今天提名、已发布）与内容审核是否开启；待裁决表带渲染图（网页作品的审核截图，没有时用审核后的缩略图）、标题、类型、来源、待人工原因（配置要求人工审核，还是自动审核未通过后转人工）与剩余时间，行动作批准、拒绝（确认框）与隔离预览（只对网页作品显示）；选中一件，详情里是自动审核的分类结论、标记与理由，图像件，以及文件清单。标签底部列出打开着的隔离预览。拒绝通知不携带审核者写下的私有理由；分类模型的说明只展示在管理页，不作为宿主指令注入聊天。

渲染图与图像件以存储地址交给 WebUI，经 `/api/media` 按文件头只下发位图；审核文件在插件数据里，页面只列名字，不提供下载，网页作品只经隔离预览查看。作品账本变了（入队、审核出结论、裁决、到期）页面重取；有待裁决的作品时发一条「需要处理」提示，标题写数量（如「3 件作品待裁决」），跳到审核页，清空后撤回；账本读取失败时发一条「出错」提示，裁决与预览一律回错误。

隔离预览只监听运行 Aalis 的机器的 `127.0.0.1`，链接令牌不落盘，裁决、撤回、超时或停用后失效。预览中的作品脚本会运行；自动审核截图则关闭页面脚本。远程 WebUI 的用户不能把此链接当作远程预览地址。不要直接在本机打开审核文件里的 HTML/SVG：直接打开没有预览服务添加的沙箱与响应头。

审核在应用启动后自动出队，热启用同样会启动。停用会中止在途流水、关预览和渲染器，并等待持久化操作；通知回合与停用相交时，已关闭插件的晚到出站会被拦住，待发状态供下次启动继续处理。未完成的条目在下次启动重新处理。账本损坏时拒绝写入和裁决，不覆盖损坏文件。

## 数据与边界

审核快照、账本及审计记录位于 `pluginData:/publish-review/`，已通过的文件位于 `public:/<作品编号>/`。公开根不参与会话 checkpoint 回滚。公开文件每次读取均核对摘要。

作品页面仍可通过 WebRTC/STUN 或预连接建立额外的网络联系，不能承诺完全阻断浏览器的网络侧信道；分类器也不能证明内容绝无私人信息。详见[安全模型](../concepts/security-model.md)。

状态通知与审核结果一起进入持久化待发队列，在应用启动后经消息网关进入 Agent，等待该通知回合处理结束。这是仅转述回合，不暴露或执行工具，避免待发重试重复创作、提名或其他操作。正常由 Agent 转述；若转述漏掉宿主正文中的已核验链接或格式不合要求，会在同一回合内受限纠正，未通过的模型原文不会出站。回合最终静默（包括纠正次数耗尽）或模型不可用、报错时，以 `[作品通知]` 开头派发宿主生成的结果正文，不发送失败的模型原文或通用模型报错。兜底仍经过出站中间件，并同样计入会话回复限速。

通知正文只包含宿主核定的状态与地址。作品标题作为非可信文本单独提供给当轮 Agent，可自然称呼作品，但标题中的网址或指令不能混入宿主正文；兜底通知只发送宿主正文。旧待发通知没有单独标题字段时仍可读取并派发。

通知被入口禁言、出站中间件拦截，或回合取消时保留待发；缺少网关时也不会直接绕过网关发送。账本的 `sent` 要等平台确认收下才记：本次通知进入 `outbound:message` 出站总线后，再等目标平台适配器给出投递回执（`OutgoingMessage.delivery`），同房其他回合的消息不算确认。没有适配器接手、平台报发送失败或一直等不到回执（最长 5 分钟）时，这条通知留待重发，并记下「已转述过」：之后重发直接派发宿主原文（`[作品通知]` 开头），不再让她转述一遍、不多跑一轮模型，同样等平台确认。平台报结果未知（回执带 `unconfirmed`，可能已经送达，如文件上传超时）时不重发，按已发出处理，免得同一条通知发两遍。平台确认不等于最终用户已读。已确认、但落盘前进程退出时可能重复通知，不承诺跨进程恰好一次。更晚的裁决会替换过时的待发状态。某个房间的通知发送失败时只推迟这一条，从 30 秒起每次翻倍、最长 1 小时后重试，不阻塞其他房间；重试间隔只在内存里，重启后从头计算；第一次失败的时刻落盘，从它算起满 24 小时后的下一次重试仍失败，就放弃这条通知，不再自动重发，在审核页「没发出的通知」列出（放弃时间、作品、来源房间与通知内容），owner 可以点「重发」从头再试；doctor 也报出已放弃的条数。多目标作品的上线通知只发一次：某个目标暂时缺席后恢复、地址未变时不重发；目标地址变更后按新地址再通知一次。
