# plugin-works-site — 作品站

把 `publish` 服务已经通过审核的作品部署到 Cloudflare Pages。它不接收白纸原件、不代替审核，也不把待审文件直接上网。提名入口见 [plugin-paper](plugin-paper.md)，审核配置见 [plugin-publish-review](plugin-publish-review.md)。

此插件需要显式安装、配置并启用。每个插件实例管理一个发布目标和一个独立 Pages 项目；可以登记多个实例，但同一宿主内目标 ID 和 `(accountId, projectName)` 均不得重复。启用后，在应用启动完成时开始后台部署；首次可以生成空作品集。`apply` 阶段读取或初始化本机状态（首次会生成并保存随机资产盐），不请求 Cloudflare。

## 配置

| 字段 | 默认 | 用途 |
|---|---|---|
| `targetId` | `works` | 白纸选择的发布目标 ID；同一宿主唯一，发布后保持稳定 |
| `basePath` | `/` | 作品集目录，如 `/draw/`；可写 `/draw`，配置会规范成末尾带 `/` |
| `accountId` | 必填，密钥字段 | 作品站所在的 Cloudflare 账号 |
| `apiToken` | 必填，密钥字段 | 有效的 Pages 写入凭据 |
| `projectName` | `aalis` | 已存在的 Direct Upload 项目 |
| `productionBranch` | `main` | 项目生产分支；不能以 `p-` 开头 |
| `siteOrigin` | 项目的 `https://<项目名>.pages.dev` | 对外主站网址，必须是 HTTPS 源，不带路径、端口或查询串 |
| `failOpen` | `false` | 期望的 Functions 超额处理设置 |
| `siteTitle` | `作品集` | 首页标题 |
| `siteIntro` | 空 | 首页简介 |

插件声明 `storage`，并跟随可选的 `publish`、`webui-server`、`doctor`。`publish` 不在场时不部署。`public:` 根由审核服务管理，作品站只通过发布服务读取已审核文件与缩略图。

建议为作品站使用独立账号与项目、仅具有所需权限并设置过期时间的 token。凭据不进入部署文件、模型上下文、站点状态页或本机部署账本。不要删除仍有公开链接的 Pages 项目，项目名称释放后旧地址可能被他人重新使用。

优先使用独立的 `pages.dev` 项目或独立域名。`siteOrigin` 是**精确的主机**，不授权任何其他主机，也不创建 DNS 记录；插件不会自动生成或继承域名。对外网址应在首次发布前确定，作品地址为 `siteOrigin + basePath + w/<作品编号>/`。例如 `siteOrigin: https://example.com`、`basePath: /draw/` 生成 `https://example.com/draw/w/<作品编号>/`。不建议为公开作品启用 Access，因为它会同时影响公开访问与分支预览。

一个 Pages 项目的生产部署覆盖整个项目，不能让两个目标实例分别管理同一项目的不同目录。`/draw/` 只限定本站生成和核验的公开文件路径；Pages 自定义域名仍按**整个主机**绑定。若该主机还有其他站点，需要由宿主已有路由或独立代理负责子路径分流；本插件不配置该路由。白纸对目标的允许列表与默认选择在白纸配置中管理，作品站的精确目标 ID 必须先由宿主登记。

## 发布与撤下

新增作品等待短暂防抖。HTML 作品先部署到随机分支，再更新主站包装页；分支名不包含群号或白纸内部标识。部署完成后核对版本标记、文件哈希和 HTTP 行为；文件既用随机查询串检查新部署，也用访客实际访问的无查询串路径检查缓存，包含首页、作品包装页的目录入口与作品资源。两种地址均通过后才回报 `live`，审核服务据此发送网址。

版本标记出现后，文件核验允许最多三分钟的内容收敛；随机查询串和无查询串路径共用同一截止时间，每次重试重新请求并核对文件，曾经不符的文件会继续纳入核验。只有全部匹配并通过后续 HTTP 安全探测才标记为已核对。期限内持续不符仍暂停自动部署并产生 `content` 告警，不发上线通知；日志记录脱敏文件路径、HTTP 状态、字节数及 SHA-256 摘要，便于区分短暂可见性问题与持续错误。

撤下优先处理，先更新主站、再更新相关作品分支。此次部署仅移除已撤作品，不夹带尚未上线的新作品。分支的路径清单、保留八天的墓碑文件和删除旧部署共同减少旧内容继续被访问的机会。

**撤下不是即时抹除。** 浏览器缓存、边缘缓存和已经保持的连接可能继续返回旧内容；已保持的连接可能持续十分钟以上。告警或部署失败时，聊天工具会说明已登记撤下，但线上可能仍可访问。

## WebUI 与诊断

启用 WebUI 后出现“作品站”页面，可以查看作品、部署记录和告警，撤下作品、重试部署、确认告警并恢复自动部署。项目设置不符、未知部署或线上内容核对失败会暂停上新；恢复前应先查明告警原因。

“对齐项目设置”只调整配置声明的 `fail_open`。其他账号、域名、项目绑定需要在 Cloudflare 控制台处理。“重新部署并清理账外部署”会先重建我方站点，再清理不在本机账本中的部署，操作前会确认。

`doctor` 报告账本读取失败、鉴权/部署异常、设置不符、即将到期的 token 和未读告警。界面中的“未核对”表示尚未获得线上结果，不是上线验收成功。

## 状态与隔离边界

默认实例的状态保存在 `pluginData:/works-site/state.json`；其他实例按实例 ID 安全编码后分别保存在 `pluginData:/works-site/instances/<编码>/state.json`。状态包含随机资产盐、作品组与随机分支的映射、当前部署、在飞部署和墓碑。读取失败会停止该实例部署，避免把旧站误认成空站；应先保存并检查原文件。

账本一旦记录部署、作品分支或墓碑，`targetId`、`accountId`、`projectName`、`productionBranch`、`siteOrigin` 和 `basePath` 就与该实例绑定。状态只保存这些字段的 SHA-256 指纹，不保存账号 ID 原文。更改其中任一项会在启用时明确拒绝，避免把旧目录的墓碑和作品解释成新站内容。旧版默认实例账本按根目录 `/` 识别。要新增其他域名或目录，请新建目标与独立 Pages 项目，并保留旧站直到其作品和墓碑完成撤下；不能只改现有实例的目录当作迁移。

主站是静态作品集。HTML 在独立作品分支的 sandbox iframe 中运行，不能读主站登录态。CSP 限制脚本、资源和网络请求；`failOpen: true` 会在 Functions 额度用尽时绕过分支中间件，此时顶层跳转和路径清单拦截不再可靠。

首页保留作品标题与发布日期，方便查找作品。进入作品链接后，HTML 作品占满浏览器视口；图片和视频在视口内等比缩放，页面不另加标题、日期、摘要或署名栏。浏览器标签标题和 iframe 的无障碍标题仍使用作品标题。作品页继续通过独立来源的 sandbox iframe、CSP 与禁止发送 referrer 的设置保护主站。

浏览器隔离不保证绝对断网：WebRTC 不完全受 `connect-src` 约束；本地 Chrome 实测还观察到 `preconnect` 建立 TCP 连接但没有发出 HTTP 请求。参见[安全模型](../concepts/security-model.md)。

## 部署故障时手工下架

先在 Aalis 登记撤下，避免恢复后重新部署该作品。如果 API 凭据或自动部署暂时不可用，在 Cloudflare 控制台处理受影响的作品分支部署，并用不包含该作品、保留相应墓碑的部署替换生产主站；只删除某一条旧部署不足以清除分支当前版本或缓存。不要删除整个 Pages 项目来释放名字。

处理后重新核对主站包装页、分支别名和仍存在的部署哈希网址。自动恢复前查看“作品站”告警，必要时执行重新部署与清理账外部署。主站的 pages.dev 地址始终存在，自定义域名并不会把它关闭；两种地址都应纳入核对。
