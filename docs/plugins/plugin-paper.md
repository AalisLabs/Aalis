# plugin-paper — 白纸

**包名**: `@aalis/plugin-paper`  
**源码**: `packages/plugin-paper/src/`

## 概述

白纸枢纽：把房间里真人提出的编码、做网页、做图或动画的任务交给远端代理（`remote-agent` 服务的提供者，如 [plugin-remote-agent-cursor](./plugin-remote-agent-cursor.md)）去做。一块「白纸」是一个长期存在的远端代理加本机的一个成品目录，代理的对话与工作区在同一块白纸的各件任务之间延续。

一件任务的流程：

1. 群友在房间里提需求，模型调 `paper_task`。宿主先在房间里回显任务名与原文，再受理、排队、按天记账。
2. 运行驱动按白纸依次开轮，跟踪到终态（单轮有时长上限），把成品取回本机的白纸根（`paper:/`），按这一轮的实际费用入账。
3. 任务到终态后，枢纽以宿主通知回到发起房间。模型用 `paper_send` 把图片、MP4 或单个网页发回；没发回的成品在之后的对话里一直有待交付提示。
4. owner 在 WebUI 白纸页查看白纸、任务、成品、账本与告警，并做换新、归档代理、清空、恢复、取消任务、放弃跟踪、核销预留与告警已读。

激活时只读本地账本、登记工具、钩子、页面与诊断项，不连网；进行中的任务在激活之后接回，完成通知在 `app:started` 之后才开始注入。

```ts
export default definePlugin({
  name: '@aalis/plugin-paper',
  displayName: '白纸',
  subsystem: 'agent',
  uses: {
    tools,
    sessionManager,
    storage,
    remoteAgent: optional(remoteAgent),
    gateway: optional(gateway),
    webui: optional(webuiServer),
    doctor: optional(doctor),
    events,
    hooks,
    lifecycle,
    logger,
    config,
  },
  apply(caps) { /* 见源码 */ },
});
```

- `storage` 须提供 `pluginData` 根（账本）与 `paper` 根（成品）。`paper` 根由 [plugin-storage-local](./plugin-storage-local.md) 内置，不用在 `roots` 里声明。
- `remote-agent` 缺席时远端任务不开，`paper_task` 回「远端代理不在场」。
- `gateway` 缺席时回显与 `paper_send` 改发 `outbound:message` 事件，出站中间件链被跳过，记 warn。
- 工具的「真人发起」判据依赖 plugin-agent 在工具调用上下文里填写的 `inbound`（见 [api-tools](../api/api-tools.md)）。不填这个字段的旧版 plugin-agent 下，白纸工具一律拒绝。

## 房间怎么开白纸

房间级的开关与上限在会话配置里（[api-session-manager](../api/api-session-manager.md)），经继承链实时解析，不随建会话、建子任务复制：

| 键 | 说明 |
|---|---|
| `paperEnabled` | 为 `true` 时本房间开启白纸，默认关 |
| `paperName` | 用插件配置 `papers` 里的同名白纸；不写则每个房间各一块，属性取 `defaults` |
| `remoteAgentTypes` | 本房间允许的远端代理类型（提供者实例 id）；须包含白纸的 `remoteAgentType`，空或缺省即关 |
| `remoteAgentRoomDailyCents` | 本房间每天金额上限（美分）；缺省或写坏按 0，即不开 |
| `remoteAgentUserDailyCents` | 每人每天金额上限（美分）；缺省不按人限制 |
| `remoteAgentUserDailyTasks` | 每人每天件数上限；缺省不按人限制 |

这些键一般只写在单个房间的会话配置里。写在平台档里，这个平台的所有房间都会继承；写在平台档的受众条目（`audience` 为 `group` 或 `private`）里，这个平台的全部群或全部私聊都会继承。两种写法诊断项都会报 warn；写的是 `paperName` 时，白纸页的「共用的房间」也会列出。受众条目不在 `getPlatformProfiles()` 的返回里，诊断项与白纸页经已登记的 IM 房间的继承链（`resolveInheritance`）看到它，这个受众还没有房间登记时看不到。onebot 群会话在群里来过一条真人消息后即登记，出现在 WebUI 会话页的「IM 房间」区（收录口径见 [session-manager 服务](../services/session-manager.md) §6.6）。

```yaml
# 在 WebUI 会话页为 <试点群会话 id> 写入
enabledToolGroups: [<该群原有分组>, paper]
paperEnabled: true
paperName: '<白纸名>'
remoteAgentTypes: ['@aalis/plugin-remote-agent-cursor']
remoteAgentRoomDailyCents: 1000
```

## 配置

| 字段 | 类型 | 默认值 | 说明 |
|---|---|---|---|
| `globalDailyCents` | number | `0` | 所有白纸合计每天能花多少（美分）；0 即不开远端任务 |
| `reserveDefaultCents` | number | `50` | 受理时按这块白纸最近 5 件已入账任务的平均费用预留额度，没有历史时用这个值（最少 1 美分） |
| `budgetTimeZone` | string | — | 每日上限在这个时区的 0 点换日（IANA 名，如 `Asia/Shanghai`）；留空取宿主进程的本地时区 |
| `maxRunMinutes` | number | `20` | 单轮时长上限，从开轮时刻算，到点取消 |
| `sendHtml` | boolean | `true` | `paper_send` 能否把单个 HTML 成品作为文件发回 |
| `sendHtmlMaxMB` | number | `5` | 单个网页的发送上限 |
| `sendMediaMaxMB` | number | `10` | 图片与视频的发送上限。onebot 出站只把不超过 10 MiB 的媒体内联发出，更大的改交宿主路径，NapCat 在容器里时读不到、发不出 |
| `pendingHintHours` | number | `24` | 待交付提示保留时长 |
| `reconcileMinutes` | number | `60` | 定期检查间隔（最小 10）：对账、补取费用、闲置归档、定期清空 |
| `taskRetentionDays` | number | `30` | 已结束的任务在账本里保留多久；轮次记录另按代理保留到代理删除为止 |
| `artifacts.maxFileMB` | number | `25` | 单个成品文件上限 |
| `artifacts.maxRunMB` | number | `50` | 每轮成品合计上限 |
| `artifacts.maxRunFiles` | number | `200` | 每轮成品文件数上限 |
| `artifacts.maxBundleMB` | number | `50` | 工程包上限 |
| `artifacts.maxPaperMB` | number | `2048` | 每块白纸目录的总占用上限；成品在清空之前一直留在本机，超过时拒收余下的文件并停开这块白纸 |
| `defaults` | 分组 | — | 不写名字的房间白纸用这组属性，具名白纸没写的字段也取这组（见下表） |
| `papers` | array | `[]` | 具名白纸；`name` 必填（小写字母、数字与连字符，最长 32 个字符），其余字段与 `defaults` 同名，留空取默认属性 |

白纸属性（`defaults` 与 `papers[]` 的项）：

| 字段 | 默认值 | 说明 |
|---|---|---|
| `remoteAgentType` | `''` | 远端代理插件实例 id；空即不开远端任务 |
| `remoteAgentEgress` | `'allowlist'` | 出网上限：`none` / `allowlist` / `open`。提供者报告的出网方式超过它时不开，报告「未知」按不限计 |
| `maxWaiting` | `5` | 一块白纸上排队与进行中的任务合计上限 |
| `maxPerUser` | — | 同一人在一块白纸上未结束的任务上限；不写即不按人限制 |
| `clearAfterDays` | `30` | 距上次清空这么久、且白纸完全空闲时自动清空 |
| `rotateAfterCents` | `300` | 代理累计花费超过它，下一件任务建新代理 |
| `idleArchiveMinutes` | `30` | 代理最后一轮结束后这么久没有新任务就归档（在定期检查时执行） |

```yaml
plugins:
  '@aalis/plugin-paper':
    globalDailyCents: 1000
    papers:
      - name: '<白纸名>'
        remoteAgentType: '@aalis/plugin-remote-agent-cursor'
        remoteAgentEgress: allowlist
```

## 工具

四个工具都在 `paper` 分组（会话的 `enabledToolGroups` 要列出它），都不声明 risk（等级 0，群友可用）。门槛由房间配置、真人判据与每日上限承担；被封禁的用户（负等级）由执行守卫挡住。返回值不含凭据与链接。

| 工具 | 资格 | 说明 |
|---|---|---|
| `paper_task` | 发起 | 交一件任务：`text` 为任务原文（按码点最多 1000 字），`name` 为任务名（最多 40 字，去掉控制字符、格式字符、行与段分隔符和「」，连续空白压成一个空格）。返回 `{ ok, taskId, position }` |
| `paper_status` | 使用 | 列本房间所用白纸上排队、进行中与 24 小时内结束的任务；给 `task_id` 时只看本房间发起的这一件，不受 24 小时限制 |
| `paper_cancel` | 发起 | 取消自己在本房间发起的任务：排队中的移出并释放预留；运行中的请远端取消这一轮，费用照常等终态入账（远端取消失败时回包只写类别，提供者报错的原文只进日志）；开轮中与取回成品中的不能取消。别的房间、别的白纸上的任务与不存在的任务回同一句「本房间的白纸上没有任务」 |
| `paper_send` | 使用 | 按成品编号把成品发回本房间 |

资格：

- **发起**（`paper_task`、`paper_cancel`）：只受理真人在房间会话本身里当面发起的回合。子会话被拒；工具调用上下文没有 `inbound`（workflow 节点、mcp-server 等）被拒；`inbound.source` 非空（定时任务、闲置触发、宿主通知等内部注入）被拒；有效授权身份的 `userId` 为空（群聊 interval 回合回填的无主体身份）被拒。
- **使用**（`paper_status`、`paper_send`）：只要求房间会话本身与入站回合，完成通知的回合里也能用。

### 受理

`paper_task` 依次核对参数、资格、房间白纸、远端条件、每日上限与队列，任何一条不满足都返回可读原因，不换用别的提供者：

- **远端条件**：房间 `remoteAgentTypes` 包含白纸的类型；提供者按实例 id 精确取得到；出网不超过白纸上限；同账号隔离成立（见下）；账本读取正常；白纸没有停开；这个提供者实例没有未读的账本外代理告警。
- **同账号隔离**：声明 `transcriptIsolation: 'shared'` 的提供者（如 Cursor），同一远端账号下的代理能互读对话。枢纽按 `ready()` 报告的 `accountKey` 计：同一账号下只给一块具名白纸，多于一块时这几块都不开；取不到 `accountKey` 的按冲突算，引用同类提供者的具名白纸都不开。拒绝理由只写宿主撰写的类别（如「提供者不可用」「远端临时故障」），它会写进任务的失败原因与完成通知，也交给模型；提供者报错的原文（如 key 无效、模型参数不成立，可能带远端说明与本机网络细节）只进诊断项与一条 warn（同一实例同一类别不重复记）；不写名字的房间白纸不能用这类提供者。
- **每日上限**：当天已花费、所有进行中的预留与本次预留之和，不超过全局金额与本房间金额；写了按人金额、按人件数时也不超过它们。每天在 `budgetTimeZone` 的 0 点换日。owner 在群里发起的任务同样计入。
- **队列**：同一白纸未结束的任务不超过 `maxWaiting`；写了 `maxPerUser` 时同一人也不超过它。
- **回显**：受理前经网关以 `source: 'system'` 在房间里发「交给远端：<任务名>」加原文，任务名与原文里的 `<`、`>` 换成全角 `＜`、`＞`，免得被平台适配器当成图片、视频或 @ 标记渲染。回显失败就不受理。

受理后记下任务、预留与当天件数，落盘，再交给运行驱动出队。

### paper_status

本房间发起的任务列出原文、状态、用时、费用与成品清单（编号、类型、大小）。远端说明截到 500 字，经 `wrapUntrustedContent` 包成不可信数据，放在所有宿主内容之后。同一块具名白纸上别的房间发起的任务只给件数与状态分布，不给原文、说明与成品编号。

### paper_send

- 只发本房间发起的任务的成品；别的白纸、同一具名白纸上别的房间的成品一律按「找不到」回。已随清空删除的成品不能发。
- 类型按文件头判定：PNG、JPEG、GIF、WebP 作为图片发，MP4 作为视频发，图片与视频不超过 `sendMediaMaxMB`；HTML 在 `sendHtml` 开启且不超过 `sendHtmlMaxMB` 时作为文件发。远端给的原扩展名必须与判定类型一致。
- 其余一律拒发并说明原因：压缩包（含工程包）、可执行文件、安装包、脚本、快捷方式、带宏的 Office 文档、SVG 各有一句原因，其他类型给出通用说明。
- 发出的文件名由宿主按任务名重写：去掉控制字符与格式字符（含双向控制符与零宽字符）、路径分隔符与 `:*?"<>|`，首尾去点和空格，截到 40 字，空了用 `aalis-paper`。附件指向白纸根里宿主命名的文件，远端给的文件名不进入会话历史。
- 交给网关即标为已交付，结果写「已交给发送队列」，不代表对方已收到。投递失败由平台适配器写一条投递失败记录进会话记忆，之后的回合看得到。同一成品可以重发。

## 运行驱动

- **队列**：每块白纸一把锁、一条队列，同一块白纸一件做完才开下一件，不同白纸并行。白纸停开、提供者实例有未读的账本外代理告警时不出队。出队时把受理时的核对按发起房间重跑一遍（房间开关与白纸指向、类型白名单、出网上限、同账号隔离），再核对一次每日上限并重记预留，不通过的任务判为失败并释放预留：受理之后 owner 关了房间的白纸、收紧了配置，排队的任务不会照旧开跑。
- **先落盘再调远端**：新建代理前，账本里已记下这个代理（建代理中）与开轮中的任务；已绑定代理开轮前，任务已记为开轮中。代理名由宿主生成不透明的 `aalis-paper-<8 位十六进制>`，不含群号、群名。
- **开轮认领**：远端开轮不幂等。结果未知时（读超时、临时故障、重启接回）先列这个代理的轮次：账本里没有的恰好一轮就认领，没有就重发，多于一轮按自唤醒事件处理；重发得到「代理忙」时同样先看账本外的轮次，恰好一轮也认领。开轮前已核查过代理上没有账本外的轮次，能认领的一轮分不出是本件开出的还是代理自己唤醒的，所以每次这样认领都记一条告警，请 owner 在远端后台核对。从没发出过结果未知的请求时，代理忙加账本外的轮次立即按自唤醒事件处理。结果未知时轮次列不出来（远端找不到这个代理除外），或重启接回时提供者等满 10 分钟仍不在场，任务不判失败，留在开轮中、预留保留，等下次触发（定期检查等）再认领：远端那一轮可能在跑，列出来之前不重发。第一次认领失败时挂一条 `claim-failed` 告警，开轮中超过 15 分钟的任务诊断项报 warn。提供者一直不可用时，owner 可以在任务表点「放弃跟踪」：任务判为失败并写明远端可能已开出一轮，预留保留，下一件任务建新代理；之后列得出这个代理的轮次时，账本外恰好一轮就记到这件任务名下（与认领一样记一条 `claim-unverified` 告警，费用照常入账后释放预留），不当成自唤醒停开白纸；没有就释放预留；多于一轮分不出，释放预留、按自唤醒处理；远端已找不到这个代理时释放预留。
- **等待上限**：开轮之前代理忙、远端临时故障、限流与取消归档的等待，每件任务合计不超过 10 分钟，超过就判失败并释放预留；开轮结果未知之后的认领除外，那时等满上限仍认领不了就留在开轮中（见上一条）。终态之后另算一份：远端暂时取不到这一轮时，任务留在取回成品中，下次触发再取，不判失败。
- **单轮时长**：每件运行中的任务一个计时器（开轮时刻加 `maxRunMinutes`），与事件流无关，远端只发心跳时也照样到点。新建代理的一轮以远端这一轮开跑的时刻为开轮时刻（提供者报告，限在发出建代理请求的时刻与收到结果的时刻之间，两边时钟可能有偏差；提供者不报时按请求时刻）：远端收到请求就开跑，建代理的响应可能要几十秒才回；请求之前取旧工程包链接、限流退避的等待不算，重启接回时远端才建出的一轮从建出时算，不会因为停机时长而刚开出就被取消。通知与任务表里的用时同样从这里算。到点请远端取消，取消按 10、30、60 秒退避仍失败就停开白纸并告警。这之后提供者一直不可用时（key 失效、提供者插件停用），owner 可以在任务表点「放弃跟踪」：任务判为失败并写明远端可能仍在运行，预留与轮次记录保留，这一轮结束后由定期检查补记费用，下一件任务建新代理。
- **终态后**：核查这个代理上有没有账本外的轮次（一次不成就留给定期对账）；取回成品；按实际费用入账，费用暂缺时 20 秒一次、共 3 次，仍缺就停开白纸，预留按临时花费保留，定期检查时再补取。费用只在这一轮到终态后取。
- **失败原因**：写进任务与完成通知的只有宿主撰写的类别（如「取回成品失败（远端找不到）」「远端拒绝开轮（远端拒绝了请求）」），远端报错的原文只进日志：原文里可能有远端可控的内容（如成品路径），通知会归档，之后每一轮都以 system 出现。白纸停开的说明同样如此：出队时提供者不可用而停开，说明只写类别（如「远端代理「…」不可用（提供者不可用）」），它会经 `paper_task` 的拒绝理由交给模型，也出现在诊断项与白纸页；原文只进日志。
- **前言**：每轮交给远端的正文是宿主写的工作约束加群友的原文。约束包括只在工作目录里工作、本件成品放进交付目录下以任务 id 命名的子目录、网页尽量做成单个自包含的 `index.html` 并附预览、每轮结束把工程打包、不设定时唤醒、不做扫描刷量与注册账号、不在外部平台部署或公开发布，以及提供者声明的约束。前言不含任何凭据。
- **换新**：代理累计花费超过 `rotateAfterCents`，或 owner 点了换新，下一件任务建新代理。不按 token 数换新：提供者报的 token 数（如 Cursor 的 `/usage`）是一轮里全部模型调用的累计，多步的一轮远超单次上下文，按它换新会让几乎每件任务都新建代理、丢掉远端对话的连续性。新代理有一轮成功取回之前，每轮前言都带旧代理工程包的位置（提供者给的链接或路径，由新代理自己取得）；成功之后删除旧代理（名下还有没入账的费用时等入账后再删）。换新只重置对话：工程包里若有群友写进工作目录的规则文件，会一起带到新代理。
- **自唤醒事件**：代理上出现账本外的轮次（远端代理能自设定时器唤醒自己）时，取消在跑的账本外轮次，它们的费用记进全局日账，停开白纸并告警，下一次新建代理不带旧工程包，删除这个代理（不只归档：定时唤醒的订阅跟着代理走）。这个代理上还有本白纸的任务时，等任务取回成品后再删。核查时机：定期对账、第一次开轮就遇到代理忙、每轮终态后、闲置归档前。
- **删除代理前结清费用**：代理删掉之后它的费用就取不到了。删除前先把远端有、账本里没有的轮次记下（例如建代理判为失败、远端其实已建出的首轮），再补取一次没入账的费用。自唤醒的代理与建代理判为失败的代理照删，仍取不到的费用按估计入账（有任务的按这件任务的预留额，账本外的轮次按这块白纸一件任务的预留额）、释放预留，并记一条「按估计入账」的告警；其余退役的代理（换新后的旧代理、清空的代理）等费用入账后再删。远端已经找不到的代理同样按估计入账后从账本移除。
- **核销预留**：已结束任务的费用一直取不到、预留一直占着额度时，owner 可以在任务表点「核销预留」：还没入账的费用按这件任务的预留额记进当天花费，预留释放，之后不再补取。任务表的花费列在预留中时显示「预留 N」。
- **定期检查**（每 `reconcileMinutes`）：清理过期的任务记录；对账账本里全部未删除的代理（跳过开轮中的），列出账号下账本外的代理并各建一条告警（未读期间停开用这个提供者实例的白纸）；补取暂缺的费用；删除退役的代理；闲置归档；定期清空。对账时列代理或列轮次失败（提供者取不全时抛错，如鉴权失败、翻页超过上限、响应形状认不出）只记 warn、不停开；按提供者实例计连续失败的对账次数（一次对账里有一次列表失败就算一次，全部列出才清零），到 3 次由诊断项报出：这期间账本外的代理与轮次查不出来。
- **清空**：取消排队的任务，删除这块白纸的远端代理与本机白纸目录，任务记录保留、成品标为已清空。有任务在开轮、运行或取回成品时拒绝。代理名下还有没入账的费用时，远端代理等费用入账后再删。
- **重启接回**：激活之后进行。开轮中的任务按原路径认领或以同一 agentId 重建；运行中的先核对时长，已超时的立即取消，其余从上次的事件位置继续；取回成品中的查一次终态后重新取回。Aalis 停机期间远端这一轮不受时长上限约束。
- 不订阅 `memory:clear`：`/clear` 不动白纸与账本。

远端找不到代理时（owner 在远端后台删了它），枢纽把这个代理连同它的轮次移出账本，下一件任务新建代理。

## 完成通知与待交付提示

任务到终态（完成、失败、超时取消、被 owner 取消）后，枢纽向发起房间注入一条宿主通知（`IncomingMessage.hostNotice`，见 [schema-message](../api/schema-message.md)）：

- 一件一条，`source` 为 `paper:<白纸 id>:<任务 id>`，各占 agent 的一条会话来源通道，互不中止；不做串行与合并。
- `actor` 为 `selfInitiatedActor(platform)`，不带 `userId`、`nickname`、`sessionType`、`triggerType`。通知不是任何人的发言，不进向量记忆与关系、档案抽取。
- `content` 只放宿主撰写的行：以 `[白纸]` 开头，写任务编号、任务名、结果、用时、花费与成品清单，有远端说明时写一句「远端说明见 paper_status <任务 id>」，有成品时提示用 `paper_send` 发回。失败原因只有宿主撰写的类别，压成一行并截到 200 字。
- 远端说明截到 800 字，经 `wrapUntrustedContent` 包好放进 `hostNotice.untrusted`。它只在通知那一轮接在正文之后出现，不归档，之后的回合与会话历史里都看不到。
- 经 `paper_cancel` 取消的任务不通知（工具结果已告知）。
- 注入之前先把通知标识与时刻记进账本并落盘，每件至多注入一次。重启前已到终态而还没注入的，在 `app:started` 之后补注。通知被禁言吞掉或那一轮失败时不重试，由待交付提示补上。

待交付提示挂在 `agent:llm:before` 上：房间里有已完成、有成品、还没发回、结束不到 `pendingHintHours` 的任务时，插一条独立的 system 消息（最后一条是 user 时插在它前面，否则追加在末尾，不碰首条系统提示），只列任务编号、任务名与成品的编号、类型、大小，不含远端说明与远端给的文件名。每次请求前先摘掉上一次的提示，工具循环的每一轮都重新判定。

## 白纸文件与账本

- 成品：`paper:/<目录>/tasks/<任务 id>/out/<产物 id>.<扩展名>`，工程包 `paper:/<目录>/workspace.tar.gz`；目录名为 `n-<白纸名>` 或 `r-<房间会话 id 的 SHA-256 前 12 位>`。文件名是宿主生成的产物 id 加按文件头判定类型的扩展名（判不出的用 `.bin`），远端给的相对路径只记在账本里供 WebUI 显示。
- 写入口对远端给的路径再净化一次（拒收绝对路径、`..`、反斜杠、控制字符与格式字符、空段），并检查单文件、每轮合计、文件数、工程包与白纸目录总占用。
- HTML 的判定：扩展名为 `.html` 或 `.htm`、能按 UTF-8 解码、去掉 BOM 与空白后以 `<!doctype html` 或 `<html` 开头（不分大小写）。
- 账本在 `pluginData:/paper/ledger.json`，经 storage 整份原子写。文件不存在时从空账本起步；存在但读不出或结构不对时失败关闭：远端任务一律不开，改账本的页面动作不执行，原文件不覆盖，诊断项报 error，等 owner 处理。

## WebUI 白纸页

页面 `paper` 分五个标签页：

| 标签页 | 内容 | 行动作 |
|---|---|---|
| 白纸 | 名字、共用的房间、远端类型、绑定代理、出网（模式与「未核实」、白纸上限）、目录占用与上限、工程包在本机的位置、停开原因 | 换新、归档代理、清空（确认框，删除远端代理与本机白纸目录）、恢复 |
| 任务 | 编号、房间、发起者、任务名、状态、用时、花费（预留中时为「预留 N」）、原文、成品数 | 取消（任何人的任务，确认框）；放弃跟踪（运行中的任务只在到点取消失败、白纸停开后可用，开轮中的任务只在开轮结果未知、认领失败后可用）；核销预留（已结束、仍占着预留的任务） |
| 成品 | 任务编号、产物编号、类型、大小、文件 | 文件单元格的「查看」「下载」 |
| 账本 | 当天全局、各房间、各发起者的花费与件数，预留中的金额 | — |
| 告警 | 时间、类别、说明、状态 | 已读（账本外代理的告警标为已读后，用这个提供者实例的白纸解除停开）。类别里 `cost-estimated` 是删除代理前费用仍取不到、按估计入账的轮次，`claim-unverified` 是开轮结果未知时认领的轮次，都请在远端后台核对；`claim-failed` 是开轮结果未知之后认领不了、留在开轮中的任务（每件只挂第一次），提供者一直不可用时可放弃跟踪 |

成品经页面动作 `readArtifact` 以 `{ name, mime, base64 }` 取回：mime 按文件头判定，只有 PNG、JPEG、GIF、WebP 给对应类型，其余（含 HTML、SVG）一律 `application/octet-stream`；文件名是产物 id 加判定类型的扩展名；超过单文件上限或已随清空删除的不读。WebUI 只把位图显示在页面里，其余只能下载（见 [api-webui](../api/api-webui.md) 的文件单元格）。工程包不经 WebUI 下载。

## 诊断项

`paper.config` 报让远端任务开不了、或让长期代理的可见范围超出预期的配置与账本问题：

- **error**：账本读取失败；同一远端账号下多于一块具名白纸；有停开的白纸；有未读的账本外代理告警。
- **warn**：取不到提供者的账号标识（写明原因，按冲突处理）；平台档的基础条目或受众条目写了 `remoteAgentTypes`；具名白纸引用的提供者不在场；一块具名白纸被多个房间、整个平台或平台的全部群（私聊）共用（长期代理的对话与工作区对它们都可见）；`globalDailyCents` 为 0；对账时列代理或列轮次连续 3 次以上失败（写提供者实例、次数与失败的类别，不写报错原文；进程重启后重新计数，提供者停用或移除后不再报）；有任务开轮中超过 15 分钟（开轮结果未知、认领不了）。
- 出网方式取自 owner 配置时，在说明里标「未核实」，不影响级别。

## 注意事项

- 一块具名白纸被多个房间共用时，任何一个房间里的群友都能经代理的对话与工作区看到别的房间交过的任务。私聊与群、不同的群不要共用一块具名白纸。
- 群友能在工作区与对话里留下影响后续任务的内容（包括改写规则文件）。换新只重置对话；要连工作区一起清掉，用清空。
- 本机下载的单文件网页在对方本地以 `file://` 打开，没有沙箱。
- 远端代理与白纸的安全边界与残余风险见 [安全模型](../concepts/security-model.md) 的「远端代理与白纸」一节。
