# plugin-memory-summary — 对话摘要压缩

**包名**: `@aalis/plugin-memory-summary`  
**源码**: `packages/plugin-memory-summary/src/index.ts`

## 概述

LLM 驱动的全量压缩：会话的用量到了自动压缩线、或会话条数到了条数线时（谁先到算谁），把切分点之前的全部活跃历史连同已有摘要压成一份新摘要，并把这些消息归档；摘要注入之后每一轮的上下文，压缩期间到达的消息原样接在摘要后面。摘要按会话分两套固定的小节结构：聊天窗口记谁在聊什么、谁在等回应与关键原话，其余会话按任务记目标、决定、改过的文件与未完成的事（见「摘要模板」）。它同时提供压缩服务 `compression`（[api-memory](../api/api-memory.md#压缩服务)），会话服务的手动压缩调它，功能位与用量条目的压缩线也看它。

摘要参与 `memory:clear` 统一清除：摘要是已归档消息的压缩，随 `context` 类型一并清理，也可单独用 `summary` 类型清理（删除会话也走这条）。清理发生在压缩途中（模型尚未返回）时，这次压缩作废：不写摘要、不归档历史、不写压缩分隔线，压缩报 `error` 并以「压缩期间会话被清空」拒绝。模型已返回、正在落库（写摘要、归档、写分隔线）时开始的清理，先等这次落库完成再删，删掉的包括刚写入的摘要。

## 插件声明

```typescript
export default definePlugin({
  name: '@aalis/plugin-memory-summary',
  provides: [compression],
  uses: {
    memory,
    llm,
    messageArchive: optional(messageArchive),
    sessionManager: optional(sessionManager),
    authority: optional(authority),
    config,
    logger,
    events,
    hooks,
    contributions,
    lifecycle,
    provide,
  },
  apply(caps) { /* 见源码 */ },
});
```

- `sessionManager`：登记会话设置项「自动压缩线」，并按会话解析它与条数线，读会话记录选摘要模板；不在场时压缩线按默认 0.8，不按条数压缩，摘要用工作模板。
- `authority`：选摘要模板时判一对一窗口的对端是不是 owner；不在场时按不是 owner。
- `messageArchive`：压成后写一条压缩分隔事件消息；不在场时不写。

## 配置

| 字段 | 类型 | 默认值 | 说明 |
|---|---|---|---|
| `summaryTokenRatio` | number | `0.05` | 摘要 Token 上限（占窗口比例）：摘要的输出上限占会话所用模型上下文窗口的比例 (0~1)，例如 0.05 表示 5%。窗口取这个会话最近一次模型调用的（还没有用量时取摘要模型的），上限不少于 512、不超过摘要模型的输出上限与它窗口的四分之一 |
| `summaryModelMode` | select | `'global'` | 摘要模型来源：global=沿用全局默认 LLM；custom=使用下方 summaryLLM 指定的模型。session（沿用会话当轮模型）暂未实现。 |
| `summaryLLM` | llm-ref | — | 摘要模型：仅当 summaryModelMode=custom 时生效；provider 为 LLM 插件实例 contextId，model 为实例内某个模型名。 |

## 会话设置项

本插件在 session-manager 上登记一个会话设置项（[api-session-manager](../api/api-session-manager.md)），各种会话都适用：

| 键 | 字段 | 显眼程度 | 没设置时 |
|---|---|---|---|
| `compressAt` | number「自动压缩线（占窗口比例）」，0 到 1 | advanced | `0.8` |

- **含义**：用量到上下文窗口的这个比例时压缩；0 表示不按用量压缩（条数线照样起作用）。压缩服务的 `compressAt(sessionId, platform)` 交出这个会话的生效值（0 时为 `undefined`）。实际在它与 agent 裁剪预算占窗口的比例中较小的那个上压缩（见下文「何时压缩」），会话服务的用量条目与界面的压缩线给的就是这个较小值。
- **层**：全局默认、平台档、平台类型档（`sessionConfig.types.<平台>.<类型名>`）、场所与单个会话按层覆盖（见 [api-session-manager](../api/api-session-manager.md)）；没有出生平台的会话（WebUI、终端）按入口平台选平台档。登记为 liveOnly：子会话按自己的继承链实时解析，不冻结父会话当时的值。哪一层都没设时为 0.8，与字段的默认值是同一个常量，没有插件配置键。
- **默认 0.8**：面向本机使用，本机可以大方用满上下文；与 agent 默认的裁剪比例 1.0 之间留出输出预留与估算误差。
- **在线平台**：在平台档（或它的平台类型档，如 `onebot` 的 `group`、`private`）上设较小的值，控制每轮的输入成本。
- **随窗口重算**：压缩线是窗口比例，同一个值在窗口差得多的模型上含义差得多。0.06 在 100 万窗口是 6 万 token；在 12.8 万窗口只有 7680 token，压不掉的人设、工具定义与注入块可能就已超过它，几乎每轮都压。换主模型时按新窗口重算在线平台的压缩线。

条数线是 [plugin-agent](./plugin-agent.md#会话设置项) 登记的会话设置项 `historyLimit`（「历史条数上限」），它同时是 agent 一轮读历史的上限。本插件按会话解析它（层与压缩线相同），会话条数到线就全量压缩，与用量到线同一条流程、同一套退避；0 或哪一层都没设时不按条数压缩。条数线与模型窗口无关，换主模型不用重算。

## 摘要模板

摘要的小节结构由插件写死，按会话选两套之一，不能自定义提示词：一份提示词同时覆盖两套模板会丢掉结构。

| 模板 | 用于 | 小节（按顺序） |
|---|---|---|
| 聊天 | 场所是聊天窗口的根会话：多方的聊天窗口（群、频道等），与对端不是 owner 的一对一窗口 | 最近在聊什么：按话题分段，写明发言人；谁有问题没回应：点名提问或请求、还没得到回答的人与问题；关键原话要点：承诺、约定、数字、链接、对助手的请求，保留发言人与原文要点 |
| 工作 | 其余会话：owner 自己的会话（WebUI、终端、owner 的 IM 私聊）、内部会话（mcp-server、编排与定时任务）与全部子会话 | 目标：要做成什么，最近一次请求照录原话；做过的决定：定下与放弃的方案及理由；改过的文件：路径与改了什么，只依据工具调用记录；未完成的事：待办列表的状态（待摘要部分里最后一次 `manage_todo_list` 的参数）、下一步 |

- **选法**：没有父会话、且房间类别（[api-session-manager](../api/api-session-manager.md) 的 `roomClass`）为 `room` 的用聊天模板，其余用工作模板。只认会话记录里的多方标记与一对一的对端，不读平台类型名、不读工作目录绑定；子会话执行任务，根会话是群也用工作模板。一对一的对端是不是 owner 问权限服务的 `isOwner`，没有权限服务时按不是 owner；没有会话管理服务时一律用工作模板。
- **共同规则**：小节标题照写、按顺序输出，没有内容的小节写「无」；系统提示写明输出上限（见下文「摘要预算」）。聊天模板另要求提到人时写成「昵称(ID)」：消息开头的 [昵称(ID)] 标注了发言人，之后才能凭 ID 或昵称认出同一个人。
- **增量合并**：已有摘要时（含分块时上一块的结果），请求要求在它的同名小节上合并更新、旧内容里仍然成立的不丢，输出完整的新摘要；已有摘要没有这些小节（没有结构的旧摘要）或小节与本模板不同（会话换了模板）时，要求把这些内容按意思归入对应小节、不保留模板之外的小节。没有结构的旧摘要因此不迁移，下一次压缩时按模板合并重写。

## 工作方式

1. **何时压缩**：agent 每次调用模型之后发 `token:usage`，本插件按会话记下最近一条带 `turnId` 的用量供判定；所有用量（含 `token:request` 的快照）的窗口另记一份，只供摘要预算用。回合结束时（`agent:turn:after`，中止或出错的回合除外）取这一轮最后一次调用的用量判一次（api-memory 的 `compressionDue`），两条线按会话与用量事件上的入口平台解析，任一到线就在后台压缩：
   - 用量一维：有效阈值 E 取「压缩线 × 窗口」与 agent 裁剪预算的较小者，用量到 E 或这一轮经过了硬裁剪（用量事件的 `trimmed`），且可压缩部分至少是 E 的一半。可压缩部分取用量事件的 `untrimmedHistory`，即按没经过硬裁剪的列表估算的历史与工具结果：裁掉的部分仍在会话里，全量压缩照样压得掉。用量是硬裁剪之后量的，可能到不了线；经过了硬裁剪就算到线：一到丢内容的地步，能压就压。
   - 条数一维：回合结束时的会话条数到条数线。会话条数是这一轮最后一次调用里来自会话历史的条数（用量事件的 `historyMessages`，含这一轮追加的工具调用与结果），结局为 replied 时再加上之后落库的最终回复；到线的这一轮结束就压，下一轮读历史之前已压完。

   快照（不带 `turnId`）与上一轮留下的用量不参与判定；这一轮开始（`agent:input:before`）之后这个会话压成过或清空过的，它的用量是按那之前的历史算的，也不判；回合进行中不在后台改动历史；这个会话正在压缩时跳过。
2. **回差与退避**：压完之后可压缩部分只剩切分点之后的几条，到不了 E 的一半，不会接着再触发；人设、工具定义这些压不掉的部分再大也不会让它空转。会话条数同理，压完只剩分隔标记与切分点之后的几条，远不到条数线。后台压缩没压成时按轮数退避（两条线同一套）：连续第 k 次没压成之后，到此后判定的第 2 的 k 次方轮（至多第 32 轮）才重试，即依次隔 2、4、8、16、32 轮，此后每 32 轮一次。不按用量又涨了多少退避：用量是硬裁剪之后量的，涨到裁剪预算就不再涨。压成或清理（含删除会话）时丢掉退避记录，被清理作废的那次不记。
3. **全量压缩**（后台与手动同一条流程）：
   - 读全部活跃历史作快照（`getHistory(sessionId, Infinity)`）。切分点是快照末尾；末尾的工具调用组没写全（快照恰好读在 agent 写这一组的几次写入之间）时退到这组的 assistant 之前，它与随后写入的结果都留在活跃历史里。
   - 切分点之前的 user、assistant、tool 与 notice 消息连同已有摘要交给摘要模型（system 消息不进，压缩分隔线这类事件标记因此也不进；assistant 消息取可见正文：落库内容是结构化输出的 JSON 信封时读 metadata 的 `visibleContent`；带工具调用的 assistant 渲染为「调用 <工具名>(参数)」，tool 结果渲染为「工具结果(工具名): …」，其中工具名按 `toolCallId` 从同段历史的 assistant `toolCalls` 反查、消息自带的 `name` 只作回落，两者的参数与正文按每条 200 字硬截断；notice 消息（宿主通知、编排或定时任务派来的指令、平台通知）渲染为「通知: …」，同样按每条 200 字硬截断）；用工作模板时，待摘要部分里最后一次待办工具 `manage_todo_list` 的参数作为最后一行，与其余各行一起分块。系统提示按会话选的模板写（见「摘要模板」）；模型调用带上会话 id 与用途「摘要」，供记账（见 [api-llm 的记账](../api/api-llm.md#记账)），思考档取模型最浅的一档。
   - 每次请求的输入加输出上限都装得下摘要模型的窗口：已有摘要按至多输出上限那么多 token 算，系统提示、请求里的固定文字与对话按每字至多 2 token 保守折算。格式化后的输入（含待办那一行）超过一块时分块：每块不超过（摘要模型窗口 − 2 × 输出上限 − 2 × 提示词字数）÷ 2 字，单条超过的切成几段；逐块增量，上一块的结果作为下一块的已有摘要，最终仍是一份摘要。
   - 落笔前重读全部活跃历史，核对前缀（切分点之前的每一条）与快照逐条相同（时间戳、角色、正文与工具调用 id）：期间回滚删了消息、或晚到的消息时间戳插进了前缀，就整次作废。
   - 落定：写摘要 → `archiveOldest(sessionId, 切分点)` 归档切分点之前的消息 → 若 `message-archive` 可用，写一条压缩分隔事件消息「对话已压缩」。归档抛错时把摘要回滚到写入前，原样抛出。
4. **没压成**：摘要模型不在（`custom` 指向的模型解析不到时，原因里点名它的 provider/model）、模型失败（含流式中途断开，半截输出丢弃）、返回空、任何一块失败、期间被清空或历史被改动，都不写摘要、不归档、不写分隔线，记一条告警、报 `error` 并以原因拒绝。摘要模型的窗口装不下提示词、已有摘要与输出上限（算出的每块不足两个字）时同样拒绝。失败时不裁切历史：全量压缩下只裁切等于丢掉整段上下文。
5. **进度与并发**：经 `session:compressing` 报 `start`、`done`、`error`，压成才报 `done`（界面据此插「对话已压缩」）。待摘要部分没有对话（历史为空、只剩分隔标记）时什么都不做、照常落定，不报进度；开始之前就失败的（记忆不在、读不出历史）只拒绝，也不报。同一会话同时只有一次压缩：手动压缩遇到在途的以「这个会话正在压缩」拒绝，后台跳过。
6. **摘要预算**：输出上限 = `summaryTokenRatio` × 这个会话最近一次用量的窗口（还没有用量时取摘要模型的窗口），下限 512，不超过摘要模型的 `maxOutputTokens`（没声明时按 4096）与它窗口的四分之一（请求里的已有摘要与输出各占至多四分之一，另一半留给提示词与对话），写进请求的 `maxTokens` 与提示词。
7. **注入**：摘要通过 `agent:prompt` 贡献点（`context` 锚位）在 LLM 调用前全文注入，由 agent 组装为头部 system 区的一条 system 消息。不按预算截断：生成时的输出上限已经限住它；换了窗口更小的模型时，下一次压缩会重写摘要，期间由 agent 的硬裁剪兜底。
8. **持久化**：摘要经 memory 服务的 metadata 接口持久化（namespace `summary`，key 为会话 ID），与对话历史共用同一存储后端（取决于所用 memory 插件）。
